# Klines Polling Fix — System Now Trading

**Status**: ✅ COMPLETE
**Date**: 2026-05-06
**Commit**: f721eb2

## Problem

System was not generating trading signals despite:
- ✅ Credentials loaded correctly
- ✅ Native orchestrator starting and running
- ✅ Market data polling loop (prices) working
- ✅ Balance sync populating ($86.66 account detected)
- ❌ **Signals stuck at 0** (signal engine never evaluated)

**Root cause**: Market data polling loop only fetched **prices** (ticker), not **klines** (candlesticks with OHLCV data needed for technical indicators).

## Solution

Modified `core_engine/native/market_data.py`:

1. **Added `_refresh_klines()` method** (parallel to `_refresh_prices()`)
   - Fetches 1m klines (100 bars) for all configured symbols
   - Caches with key `(symbol, interval, limit)`
   - Implements LRU eviction (default cache size: 64)
   - Graceful error handling per symbol (one failure doesn't block others)

2. **Updated `_run()` polling loop**
   - Now calls both `_refresh_prices()` and `_refresh_klines()` each cycle
   - Maintains separate polling intervals for stability

3. **Signal engine bridge** (already fixed in previous session)
   - Added `evaluate_with_market_data()` to `NativeSignalEngine`
   - Accesses market_data._klines cache with proper key format
   - Returns signals: `{symbol, signal_type, edge_score, timestamp}`
