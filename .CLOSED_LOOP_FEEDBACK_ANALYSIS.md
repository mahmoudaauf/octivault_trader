# Closed-Loop Feedback Analysis: Why System Isn't Self-Adjusting

## Current State: OPEN SYSTEM (Static Configuration)

The native trading system currently is **NOT a closed-loop system**. All parameters are **hard-coded at startup** and never adjust based on trading results.

```
┌─────────────────────────────────────────┐
│    STATIC CONFIGURATION AT STARTUP      │
│  (all knobs fixed from .env or defaults)│
└──────────────┬──────────────────────────┘
               │
               ▼
        [5-Phase Trading Cycle]
               │
               ├─ Signal generation (10 per cycle)
               ├─ Decision filtering (0 trades with $86.66)
               ├─ Order execution (blocked by sizing rules)
               └─ Fill tracking (waiting for trades)
               │
               ▼
        [LIVE FEEDBACK DISCARDED]
        ╭─ No adjustment to position sizing
        ├─ No adjustment to signal thresholds
        ├─ No adjustment to risk limits
        ├─ No adjustment to throughput targets
        └─ System runs same way on cycle 100 as cycle 1
```

**Result**: System generates signals but can't trade because position sizing rules don't adapt to available capital or market conditions.

## Legacy System: CLOSED LOOPS (Adaptive)

The legacy system (src/l6_governance + src/l5_strategy) has **two separate feedback loops** that ARE working:

### 1. AdaptiveCapitalEngine (L6) — Dynamic Sizing

**What it does:**
- Monitors: Win rate, win/loss streaks, drawdown, volatility, fee efficiency
- Adjusts: Position size multiplier (0.25x to 1.5x baseline)
- Updates: Every trade, reflected in next trade's sizing

**Configuration knobs** (all adjustable):
```python
ADAPTIVE_CAPITAL_ENGINE_ENABLED = True
ADAPTIVE_PERF_REVIEW_SEC = 3600          # Review every hour
ADAPTIVE_PERF_LOOKBACK_TRADES = 200      # Look at last 200 trades
ADAPTIVE_RISK_FRACTION_MIN = 0.05        # Min 5% per trade
ADAPTIVE_RISK_FRACTION_MAX = 0.35        # Max 35% per trade
ADAPTIVE_WIN_STREAK_BONUS = 0.10         # +10% on 3-trade wins
ADAPTIVE_LOSS_STREAK_PENALTY = 0.18      # -18% on 3-trade losses
ADAPTIVE_WIN_RATE_BONUS_THRESHOLD = 0.60 # Bonus if win% > 60%
ADAPTIVE_DRAWDOWN_SOFT_PCT = 2.0         # Reduce at 2% DD
ADAPTIVE_DRAWDOWN_HARD_PCT = 4.0         # Aggressive cut at 4% DD
```

**Feedback loop:**
```
Trades executed → P&L calculated → Win rate computed → Size multiplier adjusted → Next trade sized differently
```

### 2. ObjectiveFeedbackController (L2) — PI Control

**What it does:**
- Monitors: NAV pace, drawdown, win rate, fee efficiency vs. daily +2% target
- Adjusts: 3 runtime knobs using PI control
- Updates: Every 15 minutes (configurable)

**Knobs adjusted:**
```python
confidence_floor      # 0.50 to 0.85   — signal filtering threshold
size_multiplier       # 0.25 to 1.50   — position size scaling
target_throughput     # 2 to 60 trades/h — trading pace
```

**Feedback loop:**
```
NAV pace vs target → error calculated → PI controller → knob adjusted →
  next signal evaluated with new threshold → next position sized differently
```

**Example adjustment:**
```
If NAV is growing 1%/day (target 2%/day):
  → PI controller increases size_multiplier from 0.8x to 1.0x
  → Next trades are larger
  → More capital deployed per signal

If drawdown exceeds 5%:
  → Hard kill switch: stop all trading
  → confidence_floor increases to 0.85 (reject most signals)
  → System goes defensive
```

## Why Native Stack Doesn't Have This

### Design Decision: MVP vs. Enterprise

| Aspect | Native Stack (MVP) | Legacy System (Enterprise) |
|--------|-------------------|---------------------------|
| **Startup** | Fast (6 files) | Slow (145 files) |
| **Feedback loops** | 0 (static) | 2 (adaptive) |
| **Config adaptation** | No | Yes (hot reload) |
| **Risk sensitivity** | Hardcoded rules | Dynamic thresholds |
| **Capital efficiency** | Low (conservative) | High (responsive) |
| **Production ready?** | ⏳ Waiting for feedback | ✅ Yes (proven) |

### Root Cause: Architectural Decision

**Native stack prioritized**:
1. ✅ Minimal attack surface (fewer moving parts)
2. ✅ Fast startup (6 core components)
3. ✅ Simple state management (no complex aggregations)
4. ❌ **No feedback integration** (left for Phase 2)

**Legacy stack invested in**:
1. ✅ Self-optimizing behavior
2. ✅ Automatic risk adjustment
3. ✅ NAV growth targeting
4. ✅ Fee efficiency monitoring

## Why Position Sizing Is Stuck at 0 Trades

```
With $86.66 capital and 5% allocation per signal:
  → Allocation per signal = $86.66 × 5% = $4.33 USDT per symbol

Decision engine filter chain:
  1. Position size too small? ✗ YES (min $25-50 from config)
     → REJECT signal

  2. Capital allocation exhausted? ✗ (but blocked by #1)

  3. Risk limits exceeded? ✗ (but blocked by #1)

Result: 10 signals generated → ALL filtered → 0 trades executed
```

**This is happening because**:
- MIN_ENTRY_USDT = 25 (from .env)
- Available per signal = $4.33
- 4.33 < 25 → rejected

**Pro**:

**Con**:

- Requires telemetry aggregation (Prometheus metrics)
- PI controller tuning per user

---

### OPTION B: Simple Adaptive Sizing (Fast)
**Effort**: 4-5 hours
**Approach**:
1. Add feedback loop to NativeCapitalAllocator
2. Track recent win rate (last 10 trades)
3. Adjust allocation_pct dynamically:
   ```python
   if win_rate > 0.60:  # 6+ wins in 10 trades
     allocation_pct *= 1.1  # Increase by 10%
   elif win_rate < 0.40:  # 4+ losses in 10 trades
     allocation_pct *= 0.8  # Decrease by 20%
   ```
4. Store win_rate in SharedState
5. Update on every fill detection

**Result**: Modest self-adjustment without complex PI control

**Pro**:
- Lightweight (under 100 lines)
- No external dependencies
- Easy to tune

**Con**:
- Doesn't address signal filtering (confidence)
- Doesn't target NAV objectives
- Reactive, not predictive

### OPTION C: Immediate Fix (Workaround)
**Effort**: 5 minutes
**Approach**:
Lower MIN_ENTRY_USDT in .env to match available capital:
```env

# Change to (enable trades)
```

**Result**: First 17 trades execute immediately (17 × $4 ≈ $68), system starts accumulating feedback

**Pro**:
- Instant validation of live trading
- Fills provide real feedback
- No code changes needed

**Con**:
- Still not a closed loop
- Uses micro-position sizes
- No position averaging

## Conclusion

**Your question is correct**: The system is **NOT closed-loop** because:

1. ✅ Feedback IS being generated (fills, P&L in SharedState)
2. ✅ Feedback IS being tracked (trade journal, positions)
3. ❌ Feedback IS NOT being used to adjust parameters
4. ❌ No mechanism to read historical performance and adjust capital_allocator, decision_engine, or executor

**The fix exists in legacy code** (src/l6_governance/adaptive_capital_engine.py + src/l5_strategy/objective_feedback_controller.py), but it's **not integrated into native stack yet**.
