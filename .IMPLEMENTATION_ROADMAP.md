#### 2. Order Reconciliation

```python
# Every cycle:

# 2. For each open order: check if locally tracked

# 4. If locally tracked but not on exchange: mark as filled/cancelled
# 5. Update local position from confirmed fills
```

**Steps**:

#### 3. Risk Limit Enforcement
**Problem**: No drawdown limits, position size caps, or daily loss limits
**Impact**: Account can get wiped; system trades recklessly
**Effort**: Low-Medium (2 hours)
**Legacy Reference**: `src/l6_governance/risk_manager.py`

```python
# Before allowing order:
# 1. Calculate current drawdown: (nav_peak - nav_current) / nav_peak
# 2. If drawdown > max_drawdown_pct: reject order
# 3. Calculate daily P&L: today's trades
# 4. If daily_loss > daily_loss_limit_pct: reject SELL orders (protect capital)
# 5. Count open positions
# 6. If open_positions >= max_concurrent: reject new entries
```

**Steps**:
1. Add risk_limit_pct, daily_loss_pct configs
2. Calculate running drawdown from NAV history
3. Track daily P&L separately from unrealized
4. Inject risk checks into decision engine
5. Log all rejections for audit

#### 4. Arbitration Gates (Real Implementation)
**Problem**: MVP default-passes all signals (no validation)
**Impact**: Invalid signals execute (wrong symbol, bad regime, etc.)
**Effort**: Medium (2-3 hours)
**Legacy Reference**: `src/l5_strategy/arbitration_engine.py`

```python
# 6-layer gates:
# 1. Symbol format: validate symbol exists on exchange
# 2. Confidence: edge_score > min_threshold
# 3. Market regime: only trade in trending markets (if regime_check enabled)
# 4. Position conflict: don't BUY if already holding position
# 5. Liquidity: volume > min_volume for symbol
# 6. Risk: position_size doesn't exceed risk_per_symbol_pct
```

**Steps**:
1. Create ArbitrationEngine class
2. Implement each gate as separate method
3. Return passed=True/False + blocking_gates list
4. Wire into decision engine (replace default-pass)
5. Test with edge cases

## Key Decisions Going Forward

1. **WebSocket vs REST**: Implement WS only if sub-second fill confirmation needed
2. **Arbitration strictness**: Start lenient (avoid false negatives), tighten over time
3. **Capital allocation**: Fixed % fine for MVP, adaptive needed for scaling
4. **Risk limits**: Conservative defaults, user can adjust
5. **TP/SL**: Manual exit sufficient for alpha testing, auto-exit for scale-up
