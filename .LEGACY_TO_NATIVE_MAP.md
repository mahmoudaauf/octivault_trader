## Key Gaps to Fill (Check Legacy)

### 1. Position Tracking After Fills
**Issue**: Orders are placed but fills aren't tracked back to positions
**Legacy Reference**: `src/l3_portfolio/position_manager.py:update_position()`
**Key Logic**:
- Update position on fill event
- Calculate P&L
- Track entry price, mark price, quantity
- Handle partial fills

### 2. Order Reconciliation
**Issue**: Don't know if placed orders actually filled on exchange
**Legacy Reference**: `core/execution_manager.py:_reconcile_with_exchange()`
**Key Logic**:
- Query exchange for open orders
- Match against local order tracking
- Detect fills, partial fills, cancellations
- Update local state

### 3. Risk Limit Enforcement
**Issue**: No max drawdown, daily loss, position size limits
**Legacy Reference**: `src/l6_governance/risk_manager.py`
**Key Logic**:
- Track daily P&L
- Compare current drawdown to limit
- Block orders if limits exceeded
- Log violations

### 4. Exit Strategy (TP/SL)
**Issue**: No take-profit or stop-loss execution
**Legacy Reference**: `src/l4_execution/tp_sl_engine.py`
**Key Logic**:
- Calculate TP/SL from entry price
- Monitor price vs targets
- Execute exit orders
- Handle partial TP

### 5. Arbitration Gates
**Issue**: MVP default-passes all signals (no real validation)
**Legacy Reference**: `src/l5_strategy/arbitration_engine.py`
**Key Logic**:
- Symbol format validation
- Confidence thresholds
- Market regime checks
- Position conflicts
- Liquidity checks
- Risk checks

### 6. Capital Allocation Strategies
**Issue**: MVP only allocates fixed 5% per signal
**Legacy Reference**:
- `src/l6_governance/capital_allocator.py` — Base allocator
- `src/l6_governance/adaptive_capital_engine.py` — Dynamic sizing
- `src/l5_strategy/capital_velocity_optimizer.py` — Momentum-based
**Key Logic**:
- Tiered allocation (core/growth/experimental)
- Performance-based weights
- Drawdown-based throttling
- Volatility scaling

### 7. Order Path Safety
**Issue**: Direct order placement without execution manager gate
**Legacy Reference**: `core/execution_manager.py:begin_execution_order_scope()`
**Key Logic**:
- Gate all orders through single path
- Enforce nonce/idempotency
- Track order lifecycle
- Handle failures gracefully

### 8. WebSocket Integration
**Issue**: Native only uses REST polling (slow)
**Legacy Reference**: `core/ws_market_data.py`
**Key Logic**:
- User-data WebSocket for fills
- 3-tier fallback (WS API v3 → listenKey → REST)
- Fill ingestion to event bus
- Balance update routing

## Quick Reference: How to Port a Feature

1. **Locate legacy implementation** (use table above)
2. **Understand the algorithm** (read src/ code)
3. **Check for state dependencies** (what fields it reads/writes)
4. **Design native version** (fit into L0-L8 architecture)
5. **Port the logic** (adapt to native classes/methods)
6. **Add tests** (match legacy test coverage)
7. **Integrate** (wire into bootstrap and app_context)

## Current Priorities

Based on impact and dependencies:

1. **🔴 HIGH**: Position tracking after fills (blocks TP/SL, risk limits)
2. **🔴 HIGH**: Order reconciliation (blocks fill tracking, P&L calculation)
3. **🟠 MEDIUM**: Risk limit enforcement (blocks real trading)
4. **🟠 MEDIUM**: Arbitration gates (currently MVP default-pass)
5. **🟡 LOW**: WebSocket market data (polling works, just slower)
6. **🟡 LOW**: Advanced capital allocation (fixed % works for MVP)

## Testing Pattern (From Legacy)

Each component in legacy has tests at:
- `tests/` — Unit tests for the component
- `tests/test_integration_*.py` — Integration tests
- `tests/test_phase*.py` — Full cycle tests

When porting, copy test patterns:
1. Isolation tests (component alone)
2. State tests (with shared_state)
3. Integration tests (with other L0-L8 components)
4. Live tests (with exchange_client stubs)
